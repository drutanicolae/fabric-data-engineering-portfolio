# Work log — 30 October 2026

## Summary

This update records the current state of the NYC Yellow Taxi Fabric and Power BI portfolio. It follows the initial Data Quality documentation and the subsequent development of the Gold analytical model and Power BI report.

## Data platform snapshot

- Lakehouse: `lh_nyc_taxi`.
- Verified source inventory: 20 monthly Yellow Taxi Parquet files, January 2025 to August 2026.
- Latest recorded `yellow_taxi_silver`: 78,423,712 rows.
- Latest recorded `yellow_taxi_gold`: 78,423,712 rows.
- Gold reporting fact: `FactTaxiTrips`, 78,423,712 rows.
- Date dimension: `DimDate`, 9,375 rows in the latest recorded validation.
- Active Gold date relationship: `DimDate[DateKey]` to `FactTaxiTrips[PickupDateKey]`.

The Gold processing logic now prepares trip duration and grouped distance/duration bins upstream in Fabric. The feature columns include `TripDurationSeconds`, `TripDistanceBin`, `TripDistanceBinSort`, `TripDurationBin`, and `TripDurationBinSort`. This avoids relying on expensive row-level calculated columns in the Power BI model.

A separate `TaxiKeyStatistics` table stores dataset-level metrics, including total trips, median and maximum duration, zero-duration and zero-distance counts and percentages, median distance, and calculation date.

- `dim_dq_rule`
- `dq_summary`
- `dq_exceptions`
- `dq_rule_counts`
- `dq_exception_rule_bridge`

The nine configured rule categories cover negative fare, total, tip and distance values; zero distance; NULL fare and total amounts; zero duration; and duration over three hours.

Latest recorded rule counts documented for the project include:

- Zero trip distance: 2,355,175

These are recorded run results and should be refreshed after a new profiling run. Rule counts overlap and are not additive unique-trip counts.

The NULL profiling work now includes dynamic counts and percentages by column, as well as the count of rows where all selected nullable attributes are NULL. A recorded profile showed:
- `request_source`: 75,520,269 NULL values (96.2977%).
- `passenger_count`, `RatecodeID`, `store_and_fwd_flag`, `congestion_surcharge`, and `Airport_fee`: 19,327,404 NULL values each (24.6448%).
- Rows where all selected nullable fields were simultaneously NULL: 16,423,961 in the recorded result.

Missing values are reported rather than automatically replaced with zero. Percentages use the relevant dataset row count as denominator; the Bronze row count shown in the Data Quality report is a separate layer-level metric and should not be confused with the Silver/Gold row count.

## Semantic models

Two Direct Lake semantic models serve separate purposes:

- `sm_nyc_taxi_gold`: operational and financial analysis using the Gold fact, date and descriptive dimensions, and `TaxiKeyStatistics`.
- `sm_nyc_taxi_data_quality`: data-quality monitoring using the DQ outputs and rule dimension.

The Gold model uses the pickup-date relationship as its active date path. Historical records from 2001-2024 exist in very small numbers in the source, while the main verified monthly source inventory is January 2025-August 2026. Time-based report interpretation should account for this historical tail.

## Power BI report

The report, **NYC Taxi Analytics**, has two developed pages:

1. **NYC Taxi Analytics Overview** — KPI cards for total trips, fare revenue, average distance, average duration, average fare per trip, and tip rate; date filtering; trend analysis; payment-type distribution; and previous-period comparisons where configured.
2. **Data Quality** — issue counts and percentages, NULL profiling, and trip-quality findings such as negative financial values, zero distance, and duration anomalies.

The Data Quality page is intended to communicate findings and support investigation. It should not duplicate the technical pipeline-validation view.
